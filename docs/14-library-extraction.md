# 库提取与等价迁移

适用于把现有应用能力提取为 `@unif` React Native 公共库，并迁移已授权调用方的任务。能力契约仍取自所属设计与实际调用；工程接入、远端设置和发布继续采用[接入指南](../ONBOARDING.md)，不另建一套流水线。

## 确定行为边界

提取前核对来源提交、真实入口、调用方、依赖、状态归属和资源生命周期，明确本次迁移场景。记录需要保留的行为及获准改变的部分，不能仅根据组件外观或名称推断职责。

等价迁移保留 UI、样式、交互、业务流程、默认值、输入输出、错误和取消语义，以及权限校验、并发保护、身份隔离、无障碍和资源清理。仅为脱离原应用进行必要的参数化与接线；以共享代码、复用或 SDK 升级为由改变其他场景，须单独确认影响范围。

先复用现有公开能力，缺口由所属实现修复。调用迁移完成后，只清理已核实无消费者的旧实现；保留原有计划、设计和有效验收依据。不能在应用与库中长期维护同一职责的两套流程。

## 区分自有原生实现与原生依赖

| 实际能力归属 | 提取与接入要求 |
|---|---|
| 库维护自己的原生源码 | 按实际源码、平台与构建接线采用相应原生检查，并验证公开入口及宿主调用 |
| TS／TSX 库调用现有原生 SDK | 沿用 JS library 工程，声明实际依赖或 peer 依赖及宿主要求；不因依赖原生能力新增 TurboModule、Fabric 或 Swift／Kotlin 桥 |

原生 SDK 的 autolinking、Pods／Gradle、权限、初始化和平台配置仍须接入真实宿主。库没有自有原生源码，不代表它能脱离原生环境运行，也不免除所声明平台的构建与行为验收。共享模板的原生源码判据见[同步说明](13-sync.md)；不得通过增加空壳原生工程改变分类。

凭证、服务地址、文件路径和环境配置由宿主通过已有接口或必要的最小扩展提供，库负责保留相应校验与错误语义。公开源码、npm 产物、文档和示例不得嵌入真实凭证、私有环境配置或个人本机路径；示例使用无敏感信息的占位值并说明接入位置。

## 交付已有 SDK 补丁

若原应用依赖 SDK 补丁，先确认补丁解决的问题、适用版本和真实调用方，不能把补丁遗漏当作等价提取。继续采用补丁时：

补丁由已确认的归属方维护。采用宿主统一管理时，库复用该唯一来源，不在源码、Yarn 配置或 npm 包中重复保存、分发补丁，也不通过安装脚本自动修改消费者依赖。库文档声明精确 SDK 版本、所需修补能力、宿主应用与重新构建步骤；验证环境从同一维护源显式准备，并核对运行时实际解析到的 SDK 副本。

1. 固定被修补 SDK 的精确版本，由所属工程审查并保存补丁源，明确应用命令及失败处理。依赖、锁文件与宿主准备步骤应能重建同一结果。
2. 通过已确认的依赖交付或宿主安装流程应用补丁，不能仅保留本机 `node_modules` 差异。库仓的 Yarn patch、`patch-package` 或 example 配置不会因消费者安装 TS 包就自动生效。
3. 在干净消费者中从实际 tarball 安装，执行文档规定的完整安装步骤，检查 SDK 目标文件及原生构建、相关行为。复用旧安装目录或只验证补丁命令退出成功不算通过。

补丁应用位置、版本约束和更新条件写入库的接入文档。需要更换 SDK 来源、增加服务或改变既有行为时，先确认新增影响；应用私有参数不作为组织通用要求。

## 按实际消费者验收

沿用仓库门禁，再按迁移触达的场景补齐证据；不适用项说明原因。源码、单测、打包、原生构建、设备行为和真实业务验收分别报告，不能互相替代。

| 验证层级 | 必要证据 |
|---|---|
| 等价行为 | 对照来源实现与已确认契约，检查迁移后的实际入口、默认值、结果及错误；UI 在可比条件下核对样式和交互 |
| 分发与公开类型 | 构建并生成真实 npm tarball，在干净消费者中按包名和公开 exports 导入，执行类型检查与相关调用；不得依赖源码别名、深层源码路径或仓库 workspace 链接 |
| 原生宿主 | 消费实际 tarball，接入真实 SDK、平台配置和宿主参数，分别完成所声明平台的构建与相关原生行为验证 |
| 边界与收尾 | 覆盖实际涉及的取消、迟到回调、重复或并发请求、身份切换，以及文件／URI 的所有权、交接和清理 |

共享 `check-library.cjs pack`／`published` 校验产物身份与公开出口文件，不执行消费者类型检查，也不证明 SDK 补丁或原生行为成立。所需消费者检查应接入本库现有测试或[专属验证入口](03-ci.md#仓库专属验证)，不复制共享 CI。

Mock、文档站和 Expo Go 均不能替代自定义原生 SDK 的真实宿主验证。文档演示可说明界面与调用方法，但必须明确尚未验证的原生行为；构建成功也不能代替设备交互或真实业务结果。

## 审查与交付

Review 建议须人工对照需求、契约和实际代码核实后处理，不直接作为新行为或测试预期。迁移引入的缺陷在本次修复；超出等价迁移范围的已有缺陷单独记录 issue，说明影响与依据，获得授权后再改变业务行为。

交付说明列明采用的组织标准修订、迁移范围、SDK 与补丁版本、公开产物和消费者验证结果，以及尚未完成的验收。npm 发布、网站部署与应用采用按各自实际结果报告；标准文档完成或检查通过不代表这些交付已完成。原始日志与个人设备、账号和本机操作记录保存在仓库外。
