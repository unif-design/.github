# CI workflow(`.github/workflows/ci.yml`)

### 触发

```yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  merge_group:
    types: [checks_requested]
```

任何 PR + main push 都跑;合并队列(若启用)也跑。

### 并发取消

`concurrency.cancel-in-progress: true` —— 同一 ref 的旧 run 被新 push 取消,省 CI 时间。

> **标准来源**:`ci.yml` 不在各仓手维护 —— 统一模板在 `unif-design/.github` 的 `templates/workflows/ci.yml`,通过 `scripts/sync-repo.sh` 下发(见 [一键同步 sync-repo.sh](./13-sync.md))。本节描述的是「四仓最优并集」标准,改 CI 标准请改模板再 sync,不要单仓改 `ci.yml`。

### job 拓扑(`changes` 门控 + 7 个 job)

- **`actionlint`** —— 校验所有 workflow YAML / 表达式 / `run:` shell,ubuntu-latest(见下方专节);**显式 `-shellcheck=shellcheck`** 加固
- **`changes`** —— `dorny/paths-filter`,按改动文件输出 `js / android / ios / shared / code` 五个布尔;下面 lint/test/build-* 全部 `needs: changes` + `if`,**纯文档 / 无关 PR 直接 skip 掉 build**(省 CI)。
- **`lint`** —— `yarn lint && yarn typecheck`,ubuntu-latest,`if: changes.code`
- **`test`** —— `yarn test --maxWorkers=2 --coverage`,ubuntu-latest,`if: changes.code`
- **`build-library`** —— `yarn prepare`(bob build),ubuntu-latest,`if: changes.js || changes.shared`
- **`build-android`** —— turbo `build:android`,ubuntu-latest,带 turbo cache + gradle cache;JDK 用 **`distribution: temurin`**(runner toolcache 预装,避开 zulu/Azul CDN 偶发 520)
- **`build-ios`** —— turbo `build:ios`,**`macos-26` + Xcode 26.5 + `RCT_USE_PREBUILT_RNCORE=1`**(走预编译 React.xcframework,省源码编译;26.5 修好了 codegen `'memory' file not found`),带 turbo cache + Pods;`setup-xcode` pin v1.7.0

> ⚠️ **不要给 `ci.yml` 本身加 `on.paths`** —— 那会让 required check 在被过滤掉的 PR 上永远 pending、卡死 merge。跳过 build 的正确做法是 `changes` job + 各 job 的 `if`(check 仍 report success,只是 no-op skip)。
>
> Required status checks 跟着 job 走:`actionlint` 已列进 ruleset 的 6 个 required checks(`actionlint` / `lint` / `test` / `build-library` / `build-android` / `build-ios`,见 [Branch protection](./05-branch-protection.md))。`changes` **不是** required check(它永远 success,不该 gate）。**native 仓**(umeng / hms-scan)另有独立的 `native-lint.yml`,把 `lint-cpp` / `lint-kotlin` 也加进 required checks,共 8 个(见下方专节)。

### actionlint —— 防 workflow YAML / shell bug

CI 原本只 lint js/ts,**workflow 文件本身没人 lint** —— 结果 release.yml 一个 `if` 表达式漏了 YAML 引号(冒号被当 mapping 分隔符),YAML 解析失败、workflow 静默不注册,一路漏到了 main(详见 [排查:release.yml if 表达式含冒号](./11-troubleshooting.md#releaseyml-if-表达式含冒号导致-workflow-不注册))。加一个 `actionlint` job 就能在 PR 阶段拦下这类问题:

- **校验范围**:所有 `.github/workflows/*.yml` 的 YAML 结构、`${{ }}` 表达式、`uses:` 引用、以及 `run:` 里的 shell —— shell 那部分靠 actionlint 调 shellcheck。标准模板**显式断言 `shellcheck --version` + 传 `-shellcheck=shellcheck`**(`ubuntu-latest` 预装 shellcheck),防 runner 未来变更导致 shell 检查静默降级(纯靠 PATH 自动探测时,shellcheck 一旦不在 PATH 会无声跳过)。
- **首跑收益**:除了拦 YAML bug,还顺手清掉了模板遗留的 `SC2086`(`$VAR` 没加双引号)、引用不存在 step 的死 `if` 等历史问题
- **实现**:下载 **pinned 版本**的二进制跑,**不要** `curl ... | bash` 执行远程脚本(远程脚本可被改,等于又一个供应链口子):

```yaml
actionlint:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6.0.2
    - name: Run actionlint
      run: |
        ACTIONLINT_VERSION=1.7.12
        curl -sSfL "https://github.com/rhysd/actionlint/releases/download/v${ACTIONLINT_VERSION}/actionlint_${ACTIONLINT_VERSION}_linux_amd64.tar.gz" | tar -xz actionlint
        shellcheck --version
        ./actionlint -color -shellcheck=shellcheck
      shell: bash
```

### 第三方 action 一律 pin 到 commit SHA

workflow 里所有 `uses:` **不写浮动 tag(`@v5`),pin 到 40 位 commit SHA**,后面用注释标版本:

```yaml
uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6.0.2
```

| 写法 | 风险 / 收益 |
|---|---|
| `@v5` / `@main`(浮动)| ❌ tag 可被作者或攻击者移到恶意 commit —— 供应链攻击常见入口 |
| `@<40位 SHA>` # vX.Y.Z | ✅ SHA 不可变,锁死代码;注释保留人类可读版本号;升级时人工核对 release / commit 后更新 SHA 与注释 |

> ⚠️ **GitHub Pages 三件套特别注意**:`actions/configure-pages` / `upload-pages-artifact` / `deploy-pages` 的 **major 版本和 artifact backend 版本绑定**。旧 major 依赖的 artifact **v3 backend 已停用**,旧 major 会随之失效。pin 它们时要顺带升到**当前 latest major**(react-native-design `deploy-docs.yml` 用的是 `configure-pages@v6` / `upload-pages-artifact@v5` / `deploy-pages@v5`),否则 deploy 会突然报 artifact 相关错误。

### 缓存策略

- `node_modules` + `.yarn/install-state.gz` —— 缓存 key 含 `yarn.lock` + `package.json`
- turbo 缓存 —— Android / iOS 各一份,key 含 `yarn.lock`
- Gradle wrapper / caches —— Android job 单独
- 缓存命中时跳过 JDK 装、跳过 Xcode 装、跳过 pod install

详见 `.github/actions/setup/action.yml`(composite action)。

### native lint(`.github/workflows/native-lint.yml`)—— 仅 native 仓

**只下发给有手写 native 源码的仓**(`react-native-umeng` / `react-native-hms-scan`,有 `.kt` + `.mm`)。`react-native-design`(纯 JS)、`react-native-camera`(vision-camera wrapper,无自有 native)**不下发**。由 `sync-repo.sh` 按 `HAS_NATIVE_SRC` 条件分发(见 [一键同步 sync-repo.sh](./13-sync.md))。

两个 job,都是 **required check**(卡 merge):

- **`lint-cpp`** —— 对 `ios/` + `android/` 下的 ObjC++/C/C++(`.mm` / `.h` / `.cpp` 等)跑 `clang-format`(CI 用 apt `clang-format-18`,pin 大版本)`--dry-run --Werror` check,读仓库根 `.clang-format`
- **`lint-kotlin`** —— 对 `android/**/*.kt` 跑 `ktlint`(pin `1.8.0`)check 模式,读 `.editorconfig`

> ⚠️ **故意不加 `on.paths`** —— 跟 `ci.yml` 同款教训:给 required check 加 paths 过滤会让它在不匹配的 PR 上永远 pending、卡死 merge。native 文件没变的 PR 上,这两个 job 跑现存(已格式化)文件秒过,不影响。
>
> **工具版本 pin 死**(不用 latest):防工具升级让 required check 无故变红。本地 reformat(`lefthook.yml` 的 `clang-format` / `ktlint` pre-commit,或手动)要对齐同版本,否则本地格式化后 CI 仍可能红。

`.clang-format`(仅 native 仓,仓库根):`BasedOnStyle: LLVM` + `IndentWidth: 2` + `ColumnLimit: 120`,刻意只用跨 clang-format 版本稳定的最小选项;不设 `PointerAlignment`(留 LLVM 默认 Right = `NSString *p`,ObjC 惯例)。

### nightly RN-next build-check(`.github/workflows/nightly-build-check.yml`)—— 仅 native 仓

**advisory canary,不是 required check**(失败只通知不卡 PR),对标 reanimated 的 nightly build-check。同样只下发给 native 仓。

- **触发**:weekly cron(周日 18:00 UTC)+ `workflow_dispatch`(改本 workflow 时也跑一遍,这种 paths 过滤对非 required check 安全)
- **`detect` job**:解析 react-native 的 `next` dist-tag。只有存在 `next`(RC 窗口期)时 `build-ios` / `build-android` 才真正跑;无 RC → no-op 绿,低噪音
- **build job**:镜像 `ci.yml` 的 `build-ios` / `build-android`,但把 example app 的 RN 升到 `next` 再构建,提早发现 upstream RN 升级导致的 native 编译 breakage
- **fork guard**:`if: github.repository_owner == 'unif-design'`
